A The Front End, in Your Own Words

  • JavaScript fundamentals: At the start of the term, array methods like .map(), .filter(), and .reduce() felt like syntactic riddles compared to plain for loops. What finally made them click was building interactive lists in React. Once I realized .map() is simply transforming raw database objects into JSX elements without mutating the original array, functional JavaScript clicked.
  • React: To someone in the year below: a component is like a custom HTML stamp or a function that accepts an argument (props) and returns a chunk of UI. State is definitely not just a normal variable. If you change a variable let count = 1, JavaScript updates memory, but the browser screen remains completely frozen. State (useState) tells React: "Hey, this data changed — re-render this component and update the DOM so the user actually sees it."
  • Styling and design: I used to think styling meant picking colors I liked and sprinkling random margin and padding until things stopped overlapping. What I learned from the design system exercises is that deliberate UI is built on strict constraints: picking one 4px spacing scale, enforcing contrast ratios (at least 4.5:1), and giving every color a semantic job (e.g., teal for calm buffer, red-orange for urgent deadlines).

B The Backend Half

  • Node and Express: When a server "listens", it is an active process bound to a network port (like port 3000 or 5432), waiting for incoming TCP/HTTP packets. A route is essentially a traffic router: it pairs an HTTP method and URL path (like GET /api/projects/:id) with a handler function that processes request headers/body and sends back a response.
  • REST: An API is RESTful when it organizes access around resources (nouns) and uses standard HTTP verbs to describe the action. GET reads data, POST creates, PUT/PATCH updates, and DELETE removes. An endpoint I wrote was GET /api/projects/:id/tasks, which queried the database for tasks matching that foreign key and returned a JSON array with HTTP status 200.
  • PostgreSQL: A JavaScript array lives in ephemeral server memory — if the Node process restarts or crashes, your data is gone forever. PostgreSQL gives you ACID guarantees, persistent relational storage on disk, and constraints like foreign keys and uniqueness. A query that took me an hour was calculating teammate hour allocations using a LEFT JOIN on members and tasks with COALESCE(SUM(tasks.estimated_hours), 0) GROUP BY members.id.
  • Connecting the two: What surprised me most was how fragile the bridge between frontend and backend is. A single missing CORS header (Access-Control-Allow-Origin), an unhandled asynchronous fetch() promise rejection, or sending Content-Type: text/plain instead of application/json silently breaks the entire client.

C What Clicked, and What Is Still Shaky

  • One thing that finally clicked: Asynchronous JavaScript and async/await. Early on, my UI tried to render tasks before the API response arrived, throwing undefined errors. Learning to manage loading states (const [loading, setLoading] = useState(true)) and conditional rendering solved this permanently.
  • One thing I still do not really understand: Row Level Security (RLS) policies and fine-grained authorization. While I understand basic JWT verification, writing PostgreSQL security policies that verify whether auth.uid() has permissions to join nested tables without causing infinite recursion or performance leaks is still challenging for me.
  • One bug I solved that I am proud of: In my project's login page, visiting on a mobile device produced a completely blank white screen. Because it worked on desktop, it seemed mysterious. I hooked up browser developer tools and found ReferenceError: useEffect is not defined and an uninitialized loading state variable. Fixing the missing import and setting up explicit loading states brought the page to life immediately.
  • One error message I now recognize on sight: Cannot read properties of undefined (reading 'map'). It almost always means my component tried to loop over an array that hasn't returned from the database yet because the initial state was null or undefined instead of an empty array [].

D How I Work

  • When I get stuck: At the start of the term, I would blindly tweak code in the editor and refresh repeatedly hoping it would work. Now, my first move is opening DevTools: Network tab to inspect payload/status codes, and the Console to read the exact stack trace.
  • AI tools: I use AI as an active pair programmer and tutor. However, it can occasionally introduce subtle issues. For example, during a component refactor, an AI assistant omitted essential imports like useEffect and attempted to generate overly aggressive CSS rules that caused layout jumping in my headline animation. I learned that I cannot accept AI output blindly; I have to test every line, understand the logic, and verify it in the browser.
  • Procrastination & cost: On an earlier backend milestone, I delayed setting up database foreign keys until the night before it was due. Rushing resulted in cascaded delete errors and scrambled seed data. That stress taught me to map out data models before touching UI code.
  • Habits: One habit I will keep is writing a clean design token system and wireframes before coding. One habit I will change is pushing smaller, atomic commits instead of waiting until an entire massive feature is finished.

E Looking Forward to the Final Project

  • Course dependency: My project, Deadline Buffer, leans heaviest on React state management and relational data modeling. The core screen (/projects/:id) ties together nested task arrays, start-by date algorithms, and teammate capacities — directly extending the CRUD and state-lifting patterns from our React module.
  • The biggest gap: The calculation for realistic start-by dates requires handling tricky calendar math (weekends, uneven work days, overlapping high-priority deadlines). Translating pure calendar days into realistic working hours without over-complicating the UI is my biggest technical challenge.
  • Two weeks from now: I will have a fully functioning Task Drawer and real-time buffer calculation working with database persistence, verified across both desktop and mobile viewports.
